### 1. 设计流程

基本流程是：需求-> 方案仿真和优化 -> 详细设计 -> 仿真验证。

#### 1.1 需求

假如我们要开始设计一个机械臂，一开始我们什么都没有。没有机械臂模型，没有具体的任务场景。但我们希望这个机械臂的设计尽可能具备完整的功能。

我们可以提出一些参数：自由度、大体的尺寸、大体的重量、期望的负载、期望的动力学性能（速度、加速度等）。

好的，有这些就够了。

例如，我们设计一个7自由度的拟人的机械臂。总长度和人相似，臂长为0.6m（从肩到腕），重量为10kg，期望的负载为5kg。有较高的动态性能，比如期望的最大速度为5m/s，最大加速度为10m/s^2。

#### 1.2 方案仿真和优化

有了初步的设计方向，我们需要进行方案的仿真和优化。

##### (1) 建立仿真模型

第一步就是要建立仿真模型。但是，我们只有一些设计目标，没有仿真模型。所以，我们需要先建立一个简单的仿真模型。

所以第一个工具是，根据自由度和大体的尺寸、重量，建立一个简单的机械臂模型。

在以下配置文件中定义：
```
config/config_manual_robot.yaml
```

首先定义基本参数，包括：
* 自由度数量
* link数量（如果都是驱动关节，link数量和自由度数量相同；如果有fix关节，link数量比自由度数量多）
* 预估总质量

这里，按照设想，我们定义为7自由度，7个link，总质量为10kg。

然后定义自由度。有很多定义自由度的方法，这里采用的是每个关节的坐标系和上一关节坐标系之间的空间变换关系。默认以Z轴为旋转轴。采用6个参数定义，分别是xyz+rpy。自由度定义中包含了尺寸信息。

例如，我们按照拟人的方式定义7个自由度（假如是左臂），下垂姿态为参考0位，肩部三个关节同轴，肘部两个关节同轴，腕部两个关节同轴，大臂长0.3m，小臂长0.3m。世界坐标系默认定义为x朝前，y朝左，z朝上。

那么定义如下
* 关节1为肩关节俯仰：[0, 0, 0, -90, 0, 0]
* 关节2为肩关节侧摆: [0, 0, 0.1, 0, 90, 0]
* 关节3为肩关节旋转: [0, 0, 0, -90, 0, 0]
* 关节4为肘关节俯仰: [0, 0, 0.3, 0, -90, 0]
* 关节5为肘关节旋转: [0, 0, 0, 0, 90, 0]
* 关节6为腕关节俯仰: [0, 0, 0.3, 0, -90, 0]
* 关节7为腕关节侧摆: [0, 0, 0, 90, 0, 0]

然后，定义关节类型，每个关节都是revolute类型。

前面的步骤我们已经有了一个简单的机械臂运动学模型。但是，这个模型还不够完善。我们需要进行动力学仿真。需要每个link的质量、惯性矩阵、重心位置。这显然目前也是没有准确信息的。所以，这里采用圆柱体进行估算。所以，还需要给出每个link的半径（长度由link长度决定），然后根据总质量，按照尺寸分配给每个link，根据圆柱体的惯量计算方法，可以赋予每个link一个合理的质量属性估算。

例如，定义肩部的半径为0.04，大臂半径为0.03，小臂半径为0.02.对应的link为：
```
Link1_radius: 0.04
Link2_radius: 0.04
Link3_radius: 0.04
Link4_radius: 0.03
Link5_radius: 0.03
Link6_radius: 0.02
Link7_radius: 0.02
```


> 圆柱体的惯量计算方法：
> 对于半径为r，高度为h的圆柱体，其质量为m，惯量矩阵I可以近似为（对称轴沿 z）：
> $$
I = \begin{bmatrix} \frac{1}{12}m(3r^2 + h^2) & 0 & 0 \\ 0 & \frac{1}{12}m(3r^2 + h^2) & 0 \\ 0 & 0 & \frac{1}{2}mr^2 \end{bmatrix}
> $$
> 其中，对角线元素分别表示绕x、y、z轴的转动惯量。I 是惯量，m 是质量，r 是半径，h 是长度

至此，我们建立了仿真模型的第一步。

但这还不够，接下来我们还需要进行一些额外的定义。在以下配置文件中定义：
```
config/config_modeling.yaml
```

需要定义出重力方向，这里是-z方向。这里使用的是前面定义的manul模型，所以不是urdf模型，这个是为了未来有urdf后进行验证的选项。

然后定义关节的角度范围，为了拟人，这里定义为（注意每个关节的z轴是正方向）：
```
joint_lower_limit: [-180,-45,-180,-150,-180,-45,-90]
joint_upper_limit: [60,180,180,10,180,45,90]
```

最后，定义末端负载（也包括末端执行器）。包括位置、质量和惯量。这里定义为：
```
end_load_pos: [0.1, 0, 0, 0, 1.5708, 0] # 要让坐标系z指向末端方向
end_load: 5
end_load_inertia: 0.005
```

至此，完全定义了这个机械臂的简单仿真模型。

接下来，可以运行以下命令，可视化出机械臂的模型，检验模型是否正确：
```
script_build_and_show_robot
```

也可以运行以下脚本，分别可视化出关节的运动和上下限位置，检查关节的定义是否正确：
```
script_test_joint_definition
```

作为对比，我们另外考察了两种不同的自由度配置方案，通过比较分析结果的差异来选出较优方案——这也是本仓库方案仿真与优化能力的体现。

* 关节1为肩关节侧摆：[0, 0, 0, 0, 90, 0]
* 关节2为肩关节俯仰: [0, 0.1, 0, -90, 0, 0]
* 关节3为肩关节旋转: [0, 0, 0, 0, 90, 0]

后续和方案一相同
```
joint_lower_limit: [-45,-180,-180,-150,-180,-45,-90]
joint_upper_limit: [180,60,180,10,180,45,90]
```

方案三，修改腕部关节为侧摆和旋转
* 方案一的关节7改为: [0, 0, 0, 0, 90, 0]
```
joint_lower_limit: [-180,-45,-180,-150,-180,-45,-180]
joint_upper_limit: [60,180,180,10,180,45,180]
```
```

```

##### (2) 静态分析

上一部分我们已经有了一个简单的机械臂模型。其中的自由度、尺寸、重量信息都定义了，要达到需求的负载能力和动力学性能，就需要进行仿真分析。

首先，我们进行静态分析。能够获得期望的负载时，每个关节需要多大的扭矩。

显然，在静态时，关节扭矩需要承担臂自身和末端负载的重力，在关节上产生的扭矩。显然，在不同的姿态下是不同的。力臂越大，所需扭矩越大。

首先，采用随机采样的方法，计算任意姿态下的关节扭矩需求。

在配置文件中：
```
config/config_modeling.yaml
```

定义采样数量：
```
num_sampling: 50000
```

然后执行
```
script_static_joint_load
```

将在关节允许的范围内，进行随机采样，计算关节静态扭矩需求。

方案一的结果如下图所示：
![](./fig/fig_static_torque1.png)

图中的x轴表示末端点相对基座的水平距离（代码中取末端坐标系原点的水平投影 norm(T(1:2,4))，即末端点在水平面内到基座轴线的距离，不是基座到末端的三维距离）。可以看出，肩部的pitch和roll（侧摆）关节，机械臂伸的越长，力臂越大，所需的扭矩越大。肩部yaw关节（绕手臂轴线旋转的关节，即图中的Joint 3）则是在肘部弯曲时，所需的扭矩最大，因为肘部弯曲时末端负载才能产生yaw关节的力臂。随着机械臂总长度增加，肘部需要伸直，肩部yaw关节的力臂反而减小，所需的扭矩也减小。而肘部和腕部关节，在任意姿态下都可能达到最大力臂，所以所需的扭矩受到总臂长的影响较小。

通常情况下，在机械臂的负载定义中。通常会有全臂长负载和半臂长负载的区别。就像人一样，不会总是在臂完全伸长时去操作重物。而是在操作重物时，人会不自觉地弯曲肘关节来减小力臂。

所以，在设计机械臂时，应该明确是要全臂长负载还是半臂长负载。这里，我们提供了工具，给定臂长阈值，计算出在臂长阈值以下的关节扭矩需求。例如，这里我们期望臂长是0.6m，加上末端执行器长度为0.7m。假定半臂长负载是0.4m的情况(图中黑色虚线)，可以得到5kg负载的扭矩需求如下

| 方案 | 负载需求 | Joint 1 | Joint 2 | Joint 3 | Joint 4 | Joint 5 | Joint 6 | Joint 7 |
|------|------|------|------|------|------|------|------|------|
| 方案1 | 半臂长  | 36.66 | 38.14 | 23.44 | 23.86 | 4.89 | 4.88 | 4.90 |
| 方案1 | 全臂长  | 54.95 | 54.85 | 23.79 | 23.95 | 4.89 | 4.90 | 4.90 |
| 方案2 | 半臂长  | 39.59 | 36.55 | 23.15 | 23.83 | 4.90 | 4.89 | 4.90 |
| 方案2 | 全臂长  | 57.14 | 55.02 | 23.79 | 23.90 | 4.90 | 4.90 | 4.90 |
| 方案3 | 半臂长  | 36.46 | 38.48 | 23.62 | 23.95 | 3.44 | 4.90 | 0 |
| 方案3 | 全臂长  | 54.97 | 54.99 | 23.92 | 23.95 | 3.44 | 4.90 | 0 |

> 关于上表的说明：表中“半臂长”一行为臂长阈值 0.4 m 以下（图中黑色虚线）的随机采样最大值；“全臂长”一行为**整个可达范围内的最大值**（等价于 `fun_plot_static_arm_of_force_joint_effort` 打印的 max joint torques），并不是 0.7 m 阈值下的结果——若按 0.7 m 阈值，方案1 的 Joint 1/Joint 2 约为 54.6/49.6，而不是表中的 54.95/54.85。表中数值由随机采样得到（`num_sampling: 50000`），是固定随机种子 `rng(1)` 的一次运行结果；脚本本身不固定种子，因此读者自己运行时仍会有零点几 Nm 量级的波动。下一小节的正交姿态搜索得到的最大静态扭矩不受采样影响，可精确复现。

可以看出，对于肩和肘关节，三种方案的扭矩需求都比较接近。考虑随机采样的误差，可以认为需求是相同的。而腕关节的扭矩需求，方案1和方案2都比较接近，方案3则有明显的差异。主要是最后一个关节和末端负载同轴，没有偏心则没有重力臂。缺少了一部分腕部力臂分量，Joint 5的扭矩也明显减小。

通常情况下，可以将半臂长下的静态扭矩需求，定义为关节模组的额定扭矩。也就是在半臂长下，关节模组可以无限长时间持续承受所需的末端负载，就可以进行持续的搬运工作。而其他动态操作都是有限时间的，可以短暂超越额定扭矩。至此，我们得到了关节模组的一项重要参数。

此外，实际上最大重力臂是可以得到的，不必随机搜索。以肩关节为例，水平伸直时就是最大重力臂。所以，我们也提供了这一方法，搜索每个关节在可以被90度整除的角度，以及在限位角度下的组合姿态。可以得到每个关节最大重力臂姿态，以及所需的扭矩。执行

```
script_static_max_joint_load
```
可以得到三个方案，每个关节的最大静态扭矩需求

| 方案2 | 55.14 | 55.14 | 23.96 | 23.96 | 4.9 | 4.9 | 4.9 |
| 方案3 | 55.14 | 55.14 | 23.96 | 23.96 | 3.46 | 4.9 | 0 |

这是理论上的全臂长负载需求。考虑随机采样误差，和前面的分析结果是一致的。


##### (3) 动力学分析

前面是静态分析，现在进行动力学分析。

机械臂动力学方程
$$
\tau = M(q)\ddot{q} + C(q, \dot{q}) + G(q) + F(\dot{q}) + \tau_{ext}
$$

前面的静态分析只考虑了重力和外力两项。这里考虑完整的动力学需求，进一步分析动态情况下关节所需要的扭矩。

前面的建模已经定义了质量属性，和末端负载，要求解关节扭矩，还差两部分：关节的运动（角度、角速度、角加速度），以及摩擦阻尼。

首先是定义运动的方法。在dynamics配置文件中

```
config/config_dynamics.yaml
```

定义时间步，仿真运动过程中的力，本质上是采样频率。

提供了两种定义方法：（trajectory_type参数）
1. 直接提供时间序列的运动数据。给定trajectory_data_file。
2. 提供开始和结束状态，然后通过插值实现运动规划。

开始和结束状态，可以提供关节空间、笛卡尔空间。（通过planning_space设置）

例如，按照关节空间定义，设定初末速度为0，从0位（home位形）运动到给定姿态。下面的数值就是本案例使用的运动，对应 config_dynamics.yaml 中的默认设置（方案A）：
```
start_configuration: [0,0,0,0,0,0,0]
start_velocity: [0,0,0,0,0,0,0]
end_configuration: [0.7854, -0.5236, 0.6981, -1.0472, 0.7854, 0.5236, 0.7854]  # unit: rad
end_velocity: [0,0,0,0,0,0,0]
```
即功能关节角 [45, -30, 40, -60, 45, 30, 45] deg，详见后面"动力学仿真：三个方案的定量对比"一节。

如果是按照笛卡尔空间定义，就给定初末状态的位姿和速度。这时，首先通过IK求解出关节角度。
然后可以选择采用笛卡尔空间插值或关节空间插值（interpolation_space）。选择插值方法（interpolation_method）：五次多项式插值或三次多项式插值。这里给定了初末速度，如果是五次多项式插值，默认加速度为0。

如果选择笛卡尔空间插值，末端沿直线运动，需要对每个姿态求解IK，会有较高概率出现无解情况。

接下来，插值还缺少一个关键参数。从开始到结束状态所需的时间。给出时间定义，轨迹就可以产生了。显然时间越短，所需要的速度和加速度就越大。一开始我们有定义机械臂期望的动态性能，速度或加速度。因此，可以选择给定最大末端速度或加速度，计算出轨迹最小的运行时间。显然，在给定插值方法后，速度和加速度之间是存在联系的，并不能都满足，只需要给定其中一个就可以得到唯一的时间。此外，还有一种模式，在给定关节模组的最大速度和扭矩限制下，也可以计算出最小的运行时间。

通过constraint_mode指定上述定义方法，指定后只有对应的参数才起作用。

在初末状态、插值方法确定后，实际运行的时间、可以由最大速度决定，也可以由最大加速度决定。但最大速度和最大加速度之间的关系并不直观。显然，加速度越大，可以在越短的距离内达到更高的速度。如果初末状态的距离较远时，较小的加速度就可以达到很大的速度。反之，如果距离很近，有希望获得很大的速度，那么就需要极大的加速度。

在动力学方程中，还有一个摩擦阻尼项，在当前的模型中不能体现。在这里，考虑到摩擦阻尼主要来自传动链，而摩擦阻尼模型通常是比较复杂的。因此，简单地，可以将其描述为关节传动效率，一个0-1之间的数值，表示能量损耗的比例。在不确定时可以取较低值来控制仿真的余量。

此外，考虑关节模组的传动模型，通常情况下是电机和减速器的形式。电机高转速低扭矩转动，通过减速器转化为高扭矩低转速的转动。在这个过程中，在经过减速器前，速度较高，对应的加速度也较高。因此包括电机转子、连接轴、减速器高速端等，尽管转动惯量很小，但由于角加速度大，因此也会消耗一部分扭矩。考虑传动效率的关节传动模型为

$$
\tau = (J_m + J_g) \rho^2 \ddot{q} + \frac{1}{\eta} \tau_{ext}
$$

左侧为关节实际的扭矩需求，右侧第一项是高速端消耗的扭矩，第二项才是外部负载。eta是传动效率。rho是减速比。J_m和J_g是电机转子和减速器高速端的转动惯量。

上式是**关节侧**的表达。代码中 fun_trajectory_inverse_dynamics 返回的是**电机侧**（减速器之前）的扭矩，即

$$
\tau_m = J_m \rho \ddot{q} + \frac{\tau_{out}}{\rho \eta}, \qquad \omega_m = \rho \dot{q}
$$

两者相差一个减速比（tau_joint = rho * tau_m），这也是出力图里同时给出 tau_motor 和 tau_out 两条曲线的原因。另外代码没有单独区分 J_g，高速端的惯量需要一并计入 motor_inertia。

这些参数通过传动损失参数进行定义
```
consider_transmission_loss: false
motor_inertia: [68e-6,68e-6,34e-6,46e-6,46e-6,10e-6,10e-6]   # Unit: kg*m^2
gear_ratio: [22,22,28,16.5,16.5,13.5,13.5]
transmission_efficiency: [0.85,0.85,0.9,0.85,0.85,0.85,0.85]  # between 0~1
```

##### (4) 动力学仿真：三个方案的定量对比

前面只定义了动力学仿真的方法，这里让三个方案各运行同一条指令运动，比较关节的扭矩需求。

运行方式与前面的分析一致：**通过配置文件切换方案，然后执行同一个脚本**

```
>> script_dynamics
```

每个方案需要激活的配置块如下：

| 方案 | config_modeling.yaml | config_manual_robot.yaml | config_dynamics.yaml |
|------|------|------|------|

##### (5) 随机动力学分析：三个方案的定量对比

前面两节用的都是**一条指定的运动**。但机械臂在实际使用中要执行各种各样的运动，只凭一个姿态或一条轨迹来判断关节需求是不够的。这一节在关节限位内**随机生成大量运动**，统计每一种运动的需求，从而得到与具体运动无关的关节规格建议。

**方法简述**

1. 在关节限位内均匀随机地取两个关节角 q1、q2，要求两者的末端距离不小于 `min_ee_distance`（当前配置为 0.1 m），否则重新采样；
2. 用关节空间插值把 q1 和 q2 连成轨迹，再按 `constraint_mode` 把每条轨迹缩放到同一个约束下：本节使用 **`constraint_mode = 2`（给定末端最大速度）**，即让每条轨迹的末端最大速度等于 `max_ee_velocity`，这里取**开头提出的 5 m/s**。注意第 (4) 节用的是 `constraint_mode = 1`（固定时长 2 s），两节需要各自激活 config_dynamics.yaml 中对应的注释块；
3. 对每条轨迹做正运动学（末端位置、速度、加速度）和逆动力学（关节扭矩、功率），记录每条轨迹的**最大值**；
4. 以轨迹的**运动距离**（q1 与 q2 的末端距离）为横坐标画散点图，并叠加均值与标准差；
5. 给定一个运动距离阈值（下面取 0.2 m），取该子集的 **97.72 分位数**（对应正态分布 ±2σ）作为该关节的规格建议值。

采样次数由 `config_stochastic_dynamics.yaml` 的 `num_samples` 控制。**为了能快速跑完全流程，本节把采样次数减小到 100 次**，并关闭并行计算，同时固定随机种子 `rng(1)` 以便复现。生产使用时把 `num_samples` 调大、`use_parallel` 打开即可。运行：

```
>> script_stochastic_dynamics_analysis
>> script_stochastic_dynamics_visualization
```

第一条脚本做仿真并把结果写入 `data/stochastic_dynamics/stoch_dyn.mat`，第二条读取结果、计算统计量并绘图。**需要注意**：随机采样使结果带有波动，在 100 次采样下，10% 以内的差异不宜过度解读；97.72 分位数由约 97~99 个样本估计，接近样本最大值。

从下面"结果三"可以看到，本节随机生成的运动时长在 0.09~0.96 s 之间（中位数约 0.37 s），远短于第 (4) 节的 2 s——这正是速度约束的直接后果。

3. **开头的两个指标本身互相矛盾**：要把末端加速到 5 m/s，按 10 m/s^2 的加速度限制至少需要 $v^2/(2a) = 1.25$ m 的行程，而这条臂的最大伸展只有 0.7 m。仿真实际给出的末端加速度是 87~89 m/s^2，是指标值的约 9 倍。所以"最大速度 5 m/s"和"最大加速度 10 m/s^2"不能同时成立——这正好印证了第 (3) 节所说的"速度和加速度并不能都满足，只需要给定其中一个"。
4. **腕部布局的优势在高速下减弱，但依然存在**：关节7 的需求从 58.27 / 70.55 Nm 降到 **6.25 Nm**（约 1/10），关节5 从 56.89 / 59.18 降到 46.27 Nm（-19%）。不过要注意：慢速时方案3 的关节7 几乎为零扭矩（重力项为零），高速时它仍有约 6 Nm，这是惯量耦合项——**"负载同轴就没有扭矩"只在重力主导的低速情形成立**。
5. **三个方案的差异在这个量级下不再决定选型**：肩部需求都在 400~700 Nm，方案之间的差别（10~20%）与采样波动同量级。真正决定方案能否实现的，是速度指标本身。
6. **如果想知道"现有模组最快能跑多快"，应该用 `constraint_mode = 4`**（在关节扭矩与速度限制下求最短运动时间），而不是先给定一个速度再检验是否可行。

##### (6) 工作空间分析：三个方案的定量对比

前面几节回答的是"关节能不能带动"这个力学问题。工作空间分析回答另一个问题：**末端能到达哪里、能以多少种姿态到达**。这两件事共同决定机械臂的设计，而且常常互相矛盾——前面已经看到，轴系布局会同时影响两者。

**方法简述**

1. 在一个给定的空间范围内按 `position_resolution` 生成位置网格，只保留到基座距离不超过 `arm_length` 的点；
2. 对每个位置，取 `orientation_discretization_num` 个大致均匀分布的方向作为**接近方向**（即末端坐标系 z 轴的指向）；
3. 对每个"位置 + 方向"组合，用**约束逆运动学**求解：位置约束（末端原点到达目标点）与指向约束（末端 z 轴指向给定方向），两者都满足才算可达。这是一个 5 维约束、7 自由度的求解，因此有些位置/方向组合无解；
4. 位置的可达性定义为该位置上可解方向的比例，称为**灵巧度**（dexterity，0~1）；完全无解的位置会被剔除；
5. 以灵巧度着色画出可达工作空间，并给出可达位置数、可达体积与平均灵巧度。

用到的配置项都在 config_workspace.yaml。**本节把位置分辨率放粗到 0.15 m、方向数减到 12**，否则三个方案无法在合理时间内算完（默认配置 0.05 m / 36 方向，样本量是它的 23 倍）。运行：

```
>> script_workspace_analysis
>> script_workspace_visualization
```

第一条脚本做分析并把结果写入 `data/workspace/workspace_ik.mat`，第二条读取结果并绘图。

**关于自碰撞检查**：`consider_self_collision` 在本节设为 `false`，原因是手动（圆柱）模型无法通过自碰撞检查——肩部连杆的碰撞圆柱与上臂的碰撞圆柱在肩关节处相接触（Link2 的长度为 0、没有碰撞几何体，因此两者不被当作相邻连杆），结果是**所有位形都被判为碰撞、可达位置数为 0**。自碰撞检查只有换成 URDF 模型才有意义。

**结论**

1. **轴系布局对"能到哪"几乎没有影响**：三个方案的可达位置数 246 / 265 / 245，可达体积 0.83 / 0.89 / 0.83 m^3，方案2 只大了约 8%。这与前面几节"肩部关节顺序不改变选型"的结论一致——把肩部两个关节交换顺序，工作空间基本不变。
2. **姿态能力差别很大**：平均灵巧度 0.570 / 0.594 / **0.348**，方案3 的最大灵巧度只有 0.667（方案1、2 在某些位置能到达全部 12 个方向），灵巧度 ≥0.5 的位置比例 68% / 73% / **21%**。**方案3 在降低腕部关节扭矩的同时，明显牺牲了姿态可达性**——这是同一个设计选择的两面：把最后一个关节与负载同轴，省了力矩，却也少了改变工具指向的能力（关节7 只能绕前臂轴转动）。
3. **本节对比是同口径的**：经验证（MATLAB 实测 home 位姿），三个方案的末端坐标系完全一致——末端点均为 (0, 0.1, -0.7)，末端坐标系 z 轴均为 (0, 0, -1)（沿小臂方向、竖直向下）。虽然负载偏置方式不同（方案1、2 侧向偏置 + 1.5708 rad 俯仰，方案3 轴向偏置），但两种参数化给出的末端坐标系相同，12 个接近方向都相对同一末端坐标系定义。因此方案3 灵巧度的下降是纯粹的运动学自由度损失——关节7 轴线与工具轴共线后只能使工具绕自身轴线滚转、不能再改变工具指向——不是坐标系约定差异造成的伪影。
4. **分辨率说明**：0.15 m 网格与 12 个方向意味着可达体积是粗估（每个可达位置按一个立方体计），灵巧度只能取 0/12 ~ 12/12 的离散值。细化网格会改变这些数字，但不会改变上面两条相对关系。可用 config_workspace.yaml 中的 `position_resolution` 与 `orientation_discretization_num` 重算，代价是时间（默认的 0.05 m / 36 方向约需十几小时）。

##### (7) 三个方案的汇总对比与结论

**汇总**

扭矩均按 J1~J7 顺序给出。作为对照，本案例选用的关节模组峰值能力为 135 / 135 / 67.5 / 82.8 / 82.8 / 41.4 / 41.4 Nm，峰值速度 90 / 90 / 90 / 180 / 180 / 360 / 360 rpm。

**结论**

1. **决定关节规格的是静态负载，而不是某条运动。** 半臂长额定需求（约 37 / 38 / 23 / 24 Nm）在三个方案里几乎相同，最大静态扭矩 55.14 Nm 由正交姿态搜索精确给出。一条 2 s 的典型运动只用掉 11%~15% 的峰值能力，而按 5 m/s 指标的高速运动把需求推到 400~700 Nm——**同一套关节在不同工况下的需求可以相差十倍以上**，所以必须先明确工况再谈规格。
2. **肩部关节顺序（方案1 ↔ 方案2）不是关键设计变量。** 静态上两者的最大扭矩完全相同（55.14 Nm），半臂长需求只是在两个肩关节之间重新分配（J1/J2：36.66/38.14 → 39.59/36.55，总和 74.80 → 76.14 Nm）；工作空间只差 8%（0.830 → 0.894 m^3）；只有单条运动下的瞬态扭矩分配有差别（9.67/18.82 对 13.34/14.41 Nm）。这个自由度可以让给布线、装配、结构等非力学因素。
3. **腕部是否与末端负载同轴（方案1 ↔ 方案3）是决定性的设计变量，而且是把双刃剑。**
   - 收益：末端关节扭矩归零（最大静态 4.90 → 0 Nm），肘旋转关节从 4.90 降到 3.44/3.46 Nm（-29%）；在 5 m/s 高速工况下关节7 也只有 6.25 Nm（方案1/2 为 58.27 / 70.55 Nm）。腕部两个关节的规格因此可以显著下调，而腕部位于臂末端，减重收益最大。
   - 代价：姿态能力明显下降——平均灵巧度 0.570 → 0.348，灵巧度 ≥0.5 的位置比例从 68% 降到 21%，最大灵巧度从 1.0 降到 0.667；同时肩部需求略升（5 m/s 工况下 J2 从 628.0 升到 702.7 Nm）。
   - 因此选型取决于任务：**需要以多种姿态接近目标（例如工具必须保持某个指向）→ 方案1/2；姿态要求单一、且希望腕部轻量 → 方案3。**
4. **性能指标本身需要自洽。** 5 m/s 与 10 m/s^2 不能同时成立（按 10 m/s^2 加速到 5 m/s 至少需要 1.25 m 行程，而臂长只有 0.7 m），按 5 m/s 仿真的实际末端加速度是 87~89 m/s^2，约为 10 m/s^2 的 9 倍；并且多个关节的扭矩超出当前模组的能力（关节1~4 全部超出，关节6 在三个方案下都超出，关节7 在方案1、2 超出而在方案3 仅为 6.25 Nm），部分关节的速度也超出。**要么下调速度指标后重新选型，要么用 `constraint_mode = 4` 反过来求"现役模组能跑多快"。**
5. **一条轨迹不足以定规格。** 第 (4) 节的单条 2 s 运动给出 18.82 Nm，只有最大静态值的 34%；同一套关节在随机运动下（第 (5) 节）的需求是它的 20 倍以上。**定规格应当把"最坏姿态（正交搜索）+ 随机运动统计 + 工作空间"三者合起来看，其中随机运动统计还必须带上工况约束（时间／速度／加速度／模组能力）。**
6. **本案例中"轴系布局"这一层设计变量的作用可以概括为**：肩部顺序几乎无影响；腕部同轴换来力矩、付出灵巧度；可达体积对两者都不敏感（0.827~0.894 m^3，相差 8% 以内）。也就是说，**这几个候选构型在"能到哪"上基本等价，真正的取舍发生在"用多大力"与"能摆多少姿态"之间。**

**本节的局限与不确定度**

1. 力矩绝对值来自圆柱体估算的质量惯量加一个点质量负载，适用于选型和方案比较，不适用于验证；
2. 静态随机采样存在零点几 Nm 的波动（见静态表格说明），正交姿态搜索的结果可精确复现；
3. 随机动力学的 97.72 分位由 100 次采样估计（接近样本最大值），10% 以内的差异不宜过度解读；
4. 工作空间用 0.15 m / 12 方向，可达体积是粗估；
5. 三个方案的末端坐标系经 MATLAB 实测一致（home 位姿下末端原点均为 (0, 0.1, -0.7)、末端 z 轴均为 (0, 0, -1)），因此灵巧度的横向对比是同口径的；其不确定度主要来自网格分辨率，见第 (6) 节结论 3、4；
6. 手动（圆柱）模型无法使用自碰撞检查；
7. 本案例没有实物实验或商业软件交叉验证。

#### 1.3 后续步骤：详细设计与仿真验证

回到第 1.1 节提出的四步流程：**需求 → 方案仿真和优化 → 详细设计 → 仿真验证**。本文在简化模型上完成了第二步，而**本仓库同时提供第四步的验证流程**——用真实 URDF 模型重跑同一套分析（见下文 (2)）。中间的详细设计与验证的实际跑批不在本文中展开，下面只做讨论。

**(1) 详细设计（不在本仓库的范围内）**

第三步在 CAD/3D 设计软件中完成：结构、传动、走线、装配，以及关节模组的最终选型。它的输入正是第 (7) 节给出的规格（额定/峰值扭矩、峰值速度、臂长与尺寸），输出是一个**真实的 URDF 模型**。

这一步会把简化模型里刻意做的近似替换掉：圆柱体估算的质量分布、点质量的末端负载、常值重力方向、恒定传动效率，都会换成真实的连杆几何与质量惯量、真实的减速器与电机参数、真实的关节限位；同时也会引入本文没有建模的东西——结构柔度、齿隙、摩擦与温升等。

**(2) 仿真验证（本仓库已实现该流程，只是分析方向相反）**

把真实模型放进 `urdf/`，在 `config_modeling.yaml` 中设置 `using_urdf_model: true` 与 `urdf_model` 的路径，即可用 `fun_build_robot` 得到真实模型（URDF 分支用 `importrobot` 导入，质量惯量直接来自模型文件，不再依赖圆柱体估算），随后复用第 (2)~(6) 节的全部分析。

但问题的提法要反过来。前面是"给定 5 kg 负载，求关节需要多少扭矩、多高速度"；验证阶段是"**给定已经选定的关节模组能力，反过来验证它能带多大负载、能跑多快、能覆盖多大的工作空间**"：

* **负载能力**：把 `end_load` 作为待验证的参数（给定几个候选值或做扫描），用第 (2) 节同样的两套静态分析得到扭矩，再与 `config_dynamics.yaml` 中的 `joint_peak_torque` 对比，就得到"半臂长负载 / 全臂长负载各能承载多少"。仓库没有内置的"反求负载"求解器，但因为静态分析已经现成，这只是改一个参数重跑。
* **动态性能**：用 `constraint_mode = 4`——在关节最大扭矩与速度的限制下求最短运行时间——得到"这套模组实际能跑多快"。这比前面"先假设 5 m/s、再检验是否可行"更贴近验证的语义（见第 (5) 节结论 4）。配合关节速度需求与能力包线，还可以检查模组工作在 $(\omega, \tau)$ 平面上的位置是否有余量。
* **工作空间**：同一套采样与约束 IK，换成真实模型并打开 `consider_self_collision`。这项检查在手动圆柱模型下会误判（见第 (6) 节），只有真实 URDF 才有意义；此时得到的是**真正可达**的工作空间。

两点实践注意：

1. URDF 模型下关节限位来自模型文件（`override_joint_limit: false`），`fun_build_robot` 会把这些限位回写到 `config`，所以分析脚本必须写成 `[robot, config] = fun_build_robot(config);`，才能保证后续分析用的是同一套限位；
2. 真实模型里末端执行器可能已经作为实体建模进去，若是这样就需要把 `add_end_load` 关掉，避免与 `end_load` 重复计入。

**(3) 本文结果在验证阶段的定位**

本文的所有数字都来自简化模型，用于选型与方案比较，**不能当作验证结论**：它对"哪个方案更省力、代价是什么"这类**相对判断**是可靠的，对"这套模组一定能带 5 kg 负载并以 5 m/s 运动"这类**绝对结论**则只是待验证的假设。

验证阶段还需要考虑本文未建模的因素：结构柔度与振动、齿隙、摩擦与温升、控制器带宽与跟踪误差、安全冗余与失效模式等；这些通常需要更高保真的多体/有限元仿真或实物实验来确认，而工作空间与随机动力学这类统计性结论也应当与实测数据对照。

因此整条方法链条可以概括为：**用简化模型做筛选与选型，用真实模型与实测做确认**——两者是同一套工具在两个方向上的用法。
